# Moon Clicker: слабые устройства и профиль производительности

Дата: 2026-11-04. Исходная версия: `699d231001824d2652225d422600fddf70a5747c`.

## Что измерено

45 секунд на каждый сценарий: 18 попыток клика в секунду, 9 тарелок, 4 активные луны, Клон, по 15 секунд с закрытыми панелями, магазином лун и профилем. Отдельный локальный стенд, вымышленные средства. Серверные ответы моделируются с задержкой 80 мс; Supabase и реальные аккаунты не используются. Это измеряет клиентский интерфейс, а не пропускную способность Supabase. Внешний SDK авторизации и Google Fonts в стенде исключены одинаково во всех вариантах.

Один сравнительный прогон каждого режима на доступном компьютере с 32 ГБ, экраном около 144 Гц. Результаты показывают сокращение работы; они не гарантируют такой же FPS на старом телефоне. Различия пиков JS-кучи зависят от момента сборки мусора: значительного сокращения всей JS-кучи этот тест не доказал.

## Вычислительный тест с реальным ограничением памяти

[Windows Job Object](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information) ограничил суммарную committed memory тестового процесса до **1 073 741 824 байт**, affinity — одно логическое ядро. Дополнительно V8: old space 128 МБ и semi-space 8 МБ. Тест выполнен на реальных constants/config/rules без DOM, с 9 тарелками, четырьмя лунами и эхом:

- 20 000 серверных действий (360 000 ручных кликов плюс автоматические), 501 421 засчитанный клик в конкретном прогоне.
- 10 713.8 мс суммарно, около 0.536 мс на действие.
- Пик committed memory Job: 65 187 840 байт.
- Пик RSS по выборкам: 75 874 304 байт; пик JS-кучи по выборкам: 28 832 696 байт.
- После принудительного GC: 5 450 280 байт до нагрузки и 5 180 192 после. В этом сценарии накопления удерживаемой JS-памяти не обнаружено. Это не доказывает отсутствие всех утечек браузера.

**Это ограничение памяти процесса, а не виртуальная машина с 1 ГБ общей RAM.** Полный Chrome под тем же Job не удалось запустить: GPU-процесс завершался с ACCESS_DENIED, затем `GPU process isn't usable`. Защита браузера не отключалась. Поэтому полного браузерного/GPU-теста при 1 ГБ и измерения VRAM/GPU-времени здесь нет. GPU WMI-счётчики в доступной среде также недоступны; нулевые значения вместо отсутствующих данных не подставлялись.

## Основные изменения

- Вместо 300 анимированных DOM-звёзд — один повторяемый PNG-тайл, созданный только при использовании. Максимум два варианта в кэше: 256×256 и 128×128, без умножения на devicePixelRatio. Для двух декодированных RGBA-тайлов теоретический объём 327 680 байт; фактическая VRAM браузера может отличаться.
- В репозитории нет тяжёлого набора PNG/WebP/3D-текстур: луны используют CSS-градиенты, эффекты — SVG/CSS/эмодзи. Дополнительный атлас лун не создавался: он добавил бы память и загрузки без сокращения существующих изображений. Неактивные лунные изображения заранее не растеризуются приложением.
- HP, таймер и прогресс эффектов меняются через transform вместо изменения ширины.
- Стабильные карточки баффов обновляются по полям, без полной замены DOM. Синергии перерисовываются только при изменении.
- Повторная работа интерфейса объединяется по ключам в ограниченное число задач на кадр.
- Убраны повторные сборки баффов в одном подтверждении/тике. Геометрия тарелок считывается одной группой на кадр вместо чередования записей и layout-чтений.
- Автоматический лёгкий режим для reported deviceMemory ≤2 ГБ или ≤2 логических ядер; есть ручной выбор. В нём отключены частицы, лазеры, тяжёлый backdrop blur и часть свечения, ограничены числа урона. Правила боя и награды не упрощаются.
- Боевые формулы и авторизация остаются серверными. Для небольших скалярных расчётов перенос в WebGPU добавил бы очереди, синхронизацию и память. Измеренная экономия получена удалением повторов и сокращением DOM/raster-работы, а не GPU-вычислениями игровых правил.

## Воспроизведение

Из корня репозитория, Node.js без npm-зависимостей:

```text
node tools/perf/lab-server.cjs
```

Открыть `http://127.0.0.1:8765/`, нажать Start 45 s stress benchmark. Для лёгкого режима перед стартом выбрать в настройках «Слабое устройство». JSON выводится в консоль сервера. Для исходного интерфейса можно запустить тот же стенд с `--ref 699d231001824d2652225d422600fddf70a5747c`.

Windows: скомпилировать `tools/perf/MoonPerfLauncher.cs` компилятором .NET Framework, положить рядом `MoonLogicStress.cjs`. Запустить launcher с аргументами `http://127.0.0.1:8765/ result.json logic`. Он создаёт отдельный Job с лимитом 1 ГБ; личные браузерные профили не используются. Режим без `logic` пытается запустить отдельный Chrome, но в среде Codex он заблокирован GPU-песочницей. Вспомогательные программы не меняют системные настройки и не отключают sandbox.
