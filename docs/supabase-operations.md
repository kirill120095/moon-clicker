# Supabase и сохранения

- Вход и регистрация: `src/modules/auth/`, `src/modules/network/supabase.js`, `supabase/functions/register-player/`. Игровые действия: `supabase/functions/game-actions/`. Схему и права сверяй по миграциям, существующим вызовам и фактической конфигурации проекта.
- При сбое отдельно проверяй авторизацию, загрузку сохранения и запись. Сопоставляй HTTP-статус и код ошибки с логами. Тайм-аут Data API и конфликт ревизии требуют разных проверок.
- При временном сбое сохраняй порядок очереди и UUID повторяемого действия. Используй ограниченную задержку и число попыток. При смене сессии отменяй повторы старой сессии. Проверь, что повтор покупки или ставки не списывает средства второй раз.
- Проверяй RLS и административные права запросами от обычного и разрешённого аккаунтов в пределах задачи. Ответ без авторизации не подтверждает изоляцию двух авторизованных игроков.
- При массовом изменении данных заранее определи затрагиваемые поля и способ восстановления. Учитывай ревизии сохранений, чтобы старый снимок не восстановил сброшенные значения. Не отправляй дополнительные записи диагностики в недоступную БД.
