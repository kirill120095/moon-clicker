# Фортуна: 7 барабанов и 40 типов выигрыша

Дата проверок: 2026-11-04 (UTC). База main: `eae23a9d0a1bc0eba604c1e41a168411e2783534`, повторно сверена в этой итерации.

**Эта версия заменяет промежуточный вариант с тремя барабанами.** Работа продолжена в той же `feature/fortuna-demo-slots`, с тем же артефактом и публичной ссылкой. Новая конкурирующая ветка не создавалась.

## Реализованное правило

Слоты находятся **в существующей вкладке «Фортуна»**, перед прежним колесом. Вкладка создаётся в `FortuneWheel.connect`, открывается через `window.switchShopTab('fortune')` и следует прежнему жизненному циклу авторизованной игры. Колесо и его серверная экономика не заменены.

- **7 барабанов**, один итоговый символ на каждом. Остановка последовательно 1 → 7.
- **8 равновероятных космических символов**.
- Оплачивается **3, 4, 5, 6 или 7 одинаковых в любых позициях**, без линий: 8 × 5 = **40 базовых типов выигрыша**.
- Разные группы складываются. Например, три луны и три звезды дают 75 + 75 = 150 демо-фишек.
- Для одного символа оплачивается **только его фактическое количество**. Семь лун дают одну выплату за семь, а не сумму выплат за 3 + 4 + 5 + 6 + 7.
- Пары не оплачиваются. Нет группы от трёх — выплата 0.
- На экране каждая выигравшая группа выделена своим цветом, текстовой строкой расчёта и соответствующей ячейкой таблицы. Цвет не является единственным обозначением.
- Начальный баланс **1 000 демо-фишек**; одно вращение стоит **25**. Кнопка восстанавливает только демо-фишки.
- Во время вращения обе кнопки заблокированы. Автоспина, монетизации и реальных ставок нет.

## Анимация и мобильный экран

Полные эффекты: 850 / 1050 / 1250 / 1450 / 1650 / 1850 / 2050 мс. Лёгкий режим: 650 / 810 / 970 / 1130 / 1290 / 1450 / 1610 мс и меньше промежуточных символов. Движение только через transform, без бесконечных таймеров и частиц. После остановки остаётся ровно по одному символу на каждом барабане.

При отключённых эффектах / reduced motion прокрутки нет, но остаётся блокировка повторного нажатия на 300 мс.

На широком экране все семь в одном ряду. В узкой панели — **4 + 3**, с нумерацией 01–07; все видны одновременно, без горизонтальной прокрутки. Перенос не создаёт линий: совпадения всё равно считаются по всему набору семи результатов. Таблица 8 × 5 помещается по ширине; доступна обычная вертикальная прокрутка панели.

## Изоляция и сохранение

`src/modules/ui/slots.js` не импортирует состояние игры, Supabase и экономические функции; не делает сетевых запросов. Единственный ключ — `moonclicker.fortunaDemo.v1`. Демо-баланс принадлежит браузеру, не аккаунту.

Версия данных теперь 2. При чтении промежуточного сохранения версии 1 сохраняется его демо-баланс, но старый трёхбарабанный результат не переигрывается и не оплачивается заново. Это не миграция основного сохранения игры.

Стоимость и сумма **всех** групп фиксируются одной записью перед анимацией. До остановки UI показывает баланс после списания; затем раскрывает сохранённый итог. Анимация ничего не начисляет. Перезагрузка, повторный finish и поздние callbacks не могут выплатить результат повторно. Смена вкладки, закрытие панели, скрытие страницы и disconnect завершают визуальную часть и освобождают все семь анимаций.

Если localStorage недоступен, работает сессионный баланс с видимым предупреждением. После перезагрузки такого превью демо-фишки возвращаются к 1 000. Повреждённый демо-ключ не блокирует игру; посторонние ключи не очищаются.

Сериализация и восстановление обеих групп во время spin проверены Node и браузерным адаптером Storage, но полная перезагрузка **с native persistence на обычном HTTP-origin** остаётся smoke-проверкой перед будущим merge.

## Границы патчей для параллельных ролей

Единственный интегратор ветки — геймплей-разработчик. Геймдизайнер, визуальный дизайнер и серверный разработчик передают предложения и патчи через родителя-координатора, не пишут в GitHub и не меняют рабочие файлы интегратора.

Чтобы не задерживать первый показ и не создавать конфликтующие переносы файлов, текущие точки расширения сохраняются:

- **Конфигурация и таблица:** начало `src/modules/ui/slots.js`: `DEMO_START`, `DEMO_COST`, `SLOT_REELS`, `MATCH_COUNTS`, `SLOT_SYMBOLS`. Это самостоятельные frozen-константы, не код обработчиков UI. Изменения коэффициентов — отдельное предложение, не автоматически согласованный баланс.
- **Оценка результата:** чистая экспортируемая `slotOutcome(symbols)` в том же файле. Не читает DOM, Storage или game state. Принимает семь индексов 0–7; возвращает `symbols`, `groups`, суммарные `multiplier`/`payout` и `kind`. Каждая группа содержит `symbol`, точный `count`, позиции 0–6, `multiplier`, `payout`. Порядок групп — по индексу символа. Чистая функция уже отделена от обработчиков; перенос в отдельный модуль допустим позже, когда будет реальный потребитель, но для первого показа не нужен.
- **Демо-сохранение:** отдельный класс `DemoSlotBalance`. Только он фиксирует транзакцию; не переносить начисления в визуальные callbacks.
- **Интерфейс:** класс `DemoSlots`. Hooks: `.demo-slot-reel`, `.demo-slot-strip > span`, `.demo-slot-moving`, `.demo-slot-hit`, `.demo-rule-hit`, `.demo-slots-win`, `.demo-slots-loss`, `.demo-slots-spin[aria-busy="true"]`. `data-demo-group="0"/"1"` связывает барабаны, строки расчёта и клетки выплат; `data-demo-rule="symbol-count"`, например `0-3` или `0-7`, указывает точную клетку. Эти индексы не являются суммами выплат.
- **Визуальный патч:** только scoped `css/slots.css` и согласованные additions hooks. Сохранять область `.demo-slots`, семь видимых результатов и мобильные 4+3. Высота `.demo-slot-strip > span` должна соответствовать `--demo-slot-cell`: это часть transform-анимации, а не произвольный декор.
- **Серверный core:** пока только отдельный результат для ревью. Его появление не означает подключение backend. Не добавлять сетевые вызовы, `db.action`, правки `secure-game`, БД или серверной экономики в эту демо-версию. Возможное подключение требует отдельного решения после проверки необходимости.

Для интеграции приложить базовый commit, список затронутых файлов/hooks и воспроизводимые проверки. После каждого принятого патча — полный набор тестов и при изменении UI проверка 320px.

## Статус доставки

Работа ведётся только в `feature/fortuna-demo-slots`, без merge и production deploy. В начале реализации GitHub был read-only. После нового разрешённого discovery появились write actions; ветка создана через GitHub MCP от проверенного main. Настройки доступа, аккаунт и транспорт не менялись интегратором. Текущие ссылки на commit/черновой PR фиксируются в handoff и manifest доставки, а не выдумываются заранее.

Следующий безопасный шаг — оценить ощущения **семи** барабанов. Перед будущим merge остаются перечисленные smoke-проверки. Влияние слотов на основную игру и возможное серверное подключение — отдельные решения автора.
