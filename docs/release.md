# Релиз

1. Сверь рабочую базу с `origin/main`. Перед рискованной правкой зафиксируй проверенный снимок в `backup/stable` или отдельном теге `backup/YYYY-MM-DD`. Опубликованные теги сохраняй.
2. Запусти [проверки](testing.md). При правке Edge Function сохрани её текущие исходники и настройки, сверь с базой. Определи порядок выкладки по совместимости клиента и сервера. Для совместимой серверной правки сначала публикуй функцию.
3. Если браузер загружает изменённый модуль по версионированному URL, обнови соответствующий параметр версии в `index.html`. Публикуй в `main`, когда это явно запрошено или входит в задачу.
4. Проверь результат GitHub Actions и фактическую версию на Pages. При правке Supabase проверь активную функцию и доступность нужного сценария. Обнови `backup/stable` обычным пушем после проверки. При расхождении истории сначала выясни его причину.
5. Для отката зафиксируй целевой коммит и версию функции. Если менялись обе стороны, проверь их совместимость и откатывай код согласованно. Миграции и данные требуют отдельной процедуры восстановления.
